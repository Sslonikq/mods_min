# explosionwand (Magic Wands)

Мод для **Minecraft Forge 1.20.1** (modId `explosionwand`): волшебные палочки и посохи, боссы с аренами в своих измерениях, лабиринт Некто, магический сет брони, вкладка «Магия».

## Фазы
План и текущая фаза: `ROADMAP.md`. Читай его в начале работы, делай только задачи текущей фазы.
**Одна фаза — одна сессия.** Пользователь начинает каждую фазу с чистого листа: `/clear`, затем `/next-phase`. Всё, что нужно следующей сессии, должно лежать в файлах (ROADMAP, отчёты, `docs/`), а не в памяти разговора. Закончив фазу, не начинай следующую в той же сессии — выведи блок «✅ Фаза N закрыта… /clear и /next-phase».
Задачи из других фаз не делаем, а записываем в «Следующий шаг» отчёта.

## Как собирается мод (главное отличие проекта)
Gradle и серверы Forge недоступны, поэтому мод собирается **без Gradle**:
- Код в `src/` пишется сразу с **SRG-именами** Forge (`m_21223_`, `f_19864_`), а не с обычными именами.
  Имена классов — обычные Mojang (`net.minecraft.world.entity.LivingEntity`).
- `stubs/` — заглушки API Minecraft/Forge только с теми членами, которые реально используются. Не хватает метода — допиши заглушку.
- Сборка, проверки и jar — одной командой: `python tools/build.py`.
- SRG-имя ищи через `tools/lookup.py` по понятному (yarn) имени, затем проверь обратным поиском `--srg`.

### Правила кода
- Константы enum Minecraft — только через `valueOf("ИМЯ")` (`Rarity.valueOf("EPIC")`, `HitResult.Type.valueOf("MISS")`).
- Частицы, звуки, блоки, эффекты — по строковому ID через реестр (класс `Fx`), никаких прямых ссылок на поля `Blocks`/`SoundEvents`.
- Сложное (summon с NBT, block_display, bossbar, title, сундуки, setblock со свойствами) — серверными командами через `Cmd`. Исключение: массовая постановка частей данжа (десятки тысяч блоков, команды слишком медленные) — `Dungeons.state(...)` (свойства через `StateDefinition`) + `m_7731_`; ID блоков там проверяет `tools/ids.py`.
- Эффекты палочек, которые напрямую меняют блоки (`m_7731_`/`m_46597_` в циклах), обязаны пропускать позиции данжей: `Dungeons.Shield sh = Dungeons.shield(level)` один раз на проход и `if (sh.at(pos)) continue;` (одиночная проверка — `Dungeons.protectedAt(level, pos)`), как пропускается бедрок. То же для падающих блоков: `FallingBlockEntity.m_201971_` сам убирает исходный блок без событий, поэтому перед ним — `sh.at(pos)` (так в `Debris.fling` и `BlackHole.ripBlocks`; новые вызовы `m_201971_` проверять так же).
- Облик боссов и существ — из `block_display`, едущих на невидимом хосте (гигант для боссов, marker-стойка для мелочи). Не из частиц.
- **Лимит `max_health` у мобов — 1024.** Больше задать нельзя (игра обрежет). Если боссу нужно больше — хост 1024, остальное через снижение урона в `onHurt` (см. `Boss3.HOST_HP`).
- Лямбда, реализующая функциональный интерфейс Minecraft, получает имя метода из заглушки — в заглушке должно быть SRG-имя (`DisplayItemsGenerator.m_257865_`).
- Тексты в игре — на русском (`ru_ru.json`) и английском (`en_us.json`), оба файла обновлять вместе.
- Java: `--release 17`.

## Команды
```bash
python tools/build.py                 # компиляция + проверка SRG + проверка ID + тесты + jar в dist/
python tools/build.py --install       # то же + копия jar в ~/Downloads
python tools/build.py --fast          # только компиляция и jar (для быстрых экспериментов)
python tools/lookup.py LivingEntity "^getHealth$"     # yarn-имя -> SRG
python tools/lookup.py "~item/ArmorItem" "^getType$"  # ~ = часть пути yarn-класса
python tools/lookup.py --srg m_21223_                 # SRG -> yarn (проверка смысла)
python tools/ids.py                   # только проверка строковых ID
python tools/linkcheck.py             # члены net/minecraft*/forge из байткода против настоящих jar Forge (EW_FORGE_DIR или MultiMC; нет jar -> «не проверено»)
```
Таблицы маппингов (MCPConfig `joined.tsrg`, Fabric intermediary, yarn 1.20.1, реестр 1.20.1) скачиваются при первом запуске в `.cache/maps/`.

  *WandItem / *StaffItem + логика            # палочки и посохи

stubs/                   # заглушки API (компилируются первыми)
resources/               # assets/ (текстуры, модели, lang), data/ (рецепты, измерения), META-INF/mods.toml, pack.mcmeta
tools/                   # build.py, lookup.py, ids.py
tests/                   # main-харнессы на заглушках (запускает build.py), напр. MazeTest

## Версии
- Версия мода — в `resources/META-INF/mods.toml` (`version="X.Y.Z"`); jar называется `explosionwand-1.20.1-X.Y.Z.jar`.
- Новая функциональность — минорная версия (2.2.0 → 2.3.0), только исправления — патч (2.3.0 → 2.3.1).
- Каждую выпущенную версию кратко описать в `docs/history.md`.

## Проверка: шаг готов, только если
1. `python tools/build.py` проходит: 0 неизвестных SRG-имён (в исходниках и байткоде), 0 проблем с ID, тесты OK.
2. Каждое **новое** SRG-имя проверено по смыслу: `lookup.py --srg <имя>` возвращает именно тот метод/поле.
3. Новые JSON (модели, рецепты, измерения, lang) валидны.
4. В игре мод запускает пользователь — то, что нельзя проверить без игры, перечисли в отчёте в «Проверить в игре».

## Отчёты (логи): ОБЯЗАТЕЛЬНО
После **каждого** завершённого шага (фича, фикс, баланс, рефакторинг, эксперимент), будь то основная сессия или агент:
1. Создай файл `reports/NNNN-YYYY-MM-DD-<agent>-<slug>.md`, где `NNNN` — следующий свободный номер (смотри `reports/`).
2. Заполни по шаблону `reports/_TEMPLATE.md`.
3. Старые отчёты не редактируй. Исправление — новым отчётом со ссылкой на старый.
4. Шаг не завершён, пока нет отчёта, не проходит `build.py` и пользователю не выведены git-команды.

## Git: коммиты делает пользователь
- **Никогда** не выполняй `git add`, `git commit`, `git push`, `git reset`, `git checkout` и т.п. Можно только читать: `git status`, `git diff`, `git log`.
- В конце каждого шага (после отчёта) выведи готовые команды, перечислив файлы явно (без `git add .`), отчёт шага — всегда в списке:
  ```
  git add src/com/explosionwand/Boss4.java resources/assets/explosionwand/lang/ru_ru.json reports/0002-2026-10-17-boss-engineer-whale-storm.md
  git commit -m "feat(boss): шторм в 4-й фазе Кита" -m "- молнии по меткам вокруг игроков" -m "- шквал сдувает к краю, присед спасает"
  ```
- Заголовок: `<тип>(<область>): <что сделано>`, до 72 символов. Типы: `feat`, `fix`, `balance`, `refactor`, `assets`, `build`, `docs`, `chore`.
  Области: `boss`, `arena`, `staff`, `wand`, `maze`, `armor`, `dims`, `dungeon`, `items`, `assets`, `build`, `agents`.
- Тело: по одному `-m` на пункт. Независимые изменения — отдельными коммитами.
- Команды под Windows PowerShell, пути с пробелами — в кавычках.

## Агенты (`.claude/agents/`)
| Агент | Когда звать |
|---|---|
| `mod-engineer` | предметы, палочки и посохи, измерения, лабиринт, сет брони, общие утилиты, регистрация |
| `boss-engineer` | боссы, арены, фазы, атаки, приспешники, добыча в сундуках, баланс боёв |
| `asset-engineer` | текстуры (PNG через Python/PIL), модели, lang, рецепты, JSON измерений и биомов, mods.toml |
| `build-engineer` | заглушки, SRG-имена, `tools/`, сборка и проверки, тесты-харнессы |
| `code-reviewer` | ревью перед коммитом (только чтение, пишет только свой отчёт) |

Типовой цикл: `mod-engineer` / `boss-engineer` (+ `asset-engineer`) → `build-engineer` → `code-reviewer`.

## Уборка
- Временные файлы — только в `build/`, `.cache/`, `dist/` (они в `.gitignore`), не в `src/` и не в корне.
- Готовый jar кладётся в `dist/`; в «Загрузки» — только через `--install` и только по просьбе пользователя.
- Не устанавливать пакеты без согласия пользователя; в отчёте писать, что установлено и как удалить.
- Не трогать ничего за пределами папки проекта.
