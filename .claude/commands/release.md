Аргументы: $ARGUMENTS

1. Текущая версия — `version="…"` в `resources/META-INF/mods.toml`. Новая — из аргументов. Если не указана: посмотри `git log` и отчёты с последней записи в `docs/history.md` и предложи (новая функциональность — минор, только исправления — патч); при сомнении спроси.
2. `git status` и `git diff --stat`: если есть незакоммиченные изменения кода, не относящиеся к релизу, — скажи и спроси, включать ли их.
3. Поставь версию в `mods.toml`. Поищи старую версию Grep-ом по `src/`, `resources/`, `tests/`, `README.md` — если она где-то зашита строкой, обнови.
4. `docs/history.md`: новый раздел сверху `## X.Y.Z — ДАТА` в стиле соседних записей: одна строка-итог и пункты для игрока (что появилось, что исправлено), без внутренней кухни. Источник — отчёты и коммиты с прошлой версии. Старые записи не трогай.
5. `python tools/build.py` (с `--install`, только если в аргументах есть «install» или «загрузки»). Должно пройти полностью; имя jar — `explosionwand-1.20.1-X.Y.Z.jar`.
6. Отчёт `reports/NNNN-ДАТА-main-release-X-Y-Z.md` по шаблону; в «Проверить в игре» — ссылка на `docs/ingame.md`.
7. Выведи git-команды: `chore(build): версия X.Y.Z, история` с файлами `mods.toml`, `docs/history.md`, отчёт. Тег и push — на усмотрение пользователя, сам не выполняй.
8. Напомни одной строкой: положить `dist/explosionwand-1.20.1-X.Y.Z.jar` в `mods/` инстанса вместо старого и пройти `/ingame`.
