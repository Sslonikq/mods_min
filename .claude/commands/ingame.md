Файл чек-листа: `docs/ingame.md`. Ответ пользователя (может быть пустым): $ARGUMENTS

## Если аргументов нет — показать, что проверять
1. Прочитай `docs/ingame.md`. В нём строка «Последний просмотренный отчёт: NNNN».
2. В `reports/` возьми отчёты с номером больше NNNN (кроме отчётов `code-reviewer`). Из каждого прочитай только раздел «Проверить в игре» (Grep по заголовку с `-A 25`, не весь файл).
3. Добавь новые пункты в `docs/ingame.md`: раздел `## <версия> — <тема> (отчёты NNNN, …)`, пункты `- [ ]`. Повторы слей, пункты, отменённые более поздним отчётом, не добавляй. Обнови «Последний просмотренный отчёт».
4. Выведи пользователю все невыполненные пункты, сгруппировав по тому, **где в игре** это смотреть (новый мир / Ад / конкретный данж / бой), в порядке, удобном для одного захода. К пунктам, где нужна команда (`/give`, `/tp`, `/summon`), — допиши её.
5. Скажи, какой jar нужен (версия из `mods.toml`) и лежит ли он в `mods/` инстанса (см. CLAUDE.md); сам jar никуда не копируй.

## Если пользователь написал результаты
1. Сопоставь его слова с пунктами `docs/ingame.md`. Что названо рабочим — `- [x] … (ок, ДАТА)`. Непонятно, к какому пункту относится, — спроси, не угадывай.
2. Что сломано или не нравится — оставь `- [ ]` с пометкой `→ замечание` и заведи замечание:
   - мелкое — предложи `/fix <текст>` (сам не начинай чинить);
   - крупное или несколько связанных — запиши в ROADMAP.md в раздел «Замечания пользователя (ДАТА)» словами пользователя.
3. Разделы, где всё отмечено `[x]`, сожми до одной строки `## <версия> — проверено ДАТА`.
4. Выведи: что закрыто, что осталось проверить, какие замечания заведены; затем git-команды для `docs/ingame.md` (и ROADMAP.md, если менялся). Отчёт в `reports/` для этого не нужен.
