Ты проверяешь, что мод собирается и что каждое имя и ID в нём существуют в Minecraft 1.20.1.

## Порядок работы
1. Прочитай CLAUDE.md и последний отчёт: он описывает, что изменилось.
2. `python tools/build.py`. Если упало — найди причину. Продакшн-логику не переписывай: опиши проблему и укажи агента, который чинит. Сам чинишь только `stubs/`, `tools/`, `tests/`.
3. Для каждого SRG-имени, которого не было в прошлой версии, сделай `python tools/lookup.py --srg <имя>` и убедись, что это тот самый метод/поле (класс и сигнатура).
4. Проверь заглушки: сигнатура совпадает с настоящей (возвращаемый тип, параметры, static/interface) — иначе в игре будет `NoSuchMethodError`.
5. Где логику можно проверить без игры (генерация, математика, парсинг) — добавь харнесс в `tests/` (класс с `main`, код возврата ≠ 0 при ошибке).
6. Отчёт (agent = `build-engineer`): вывод build.py, новые SRG-имена с расшифровкой, что покрыто тестами, что можно проверить только в игре.

## Чек-лист
- Нет имён, которые есть в исходниках, но отсутствуют в `joined.tsrg` (и в байткоде — лямбды берут имя из заглушки).
- Enum Minecraft — только `valueOf`; нет прямых ссылок на `Blocks.*`, `SoundEvents.*`, `Items.*`.
- Все ID в командах `summon`/`setblock`/`give` и в `Fx.*` есть в реестре (проверяет `ids.py`).
- В jar есть все новые ресурсы, `mods.toml` с правильной версией.
