# Конвейер данжей (фаза 4.1)

Как устроены данжи в обычном мире и как добавить новый (для 4.2+). Рабочий пример — «Тестовый разлом» (`Dungeons.RIFT`).

## Почему не JSON-структуры Minecraft
Структуры через `data/.../worldgen/structure*/` без Gradle не проверить: ошибка в JSON ломает загрузку мира, а игры у нас в цикле нет. Поэтому данж ставится кодом: шаблоны блоков (`.nbt`) читает свой читатель (`Nbt`, `DungeonTemplate`), а ставит `Dungeons` по детерминированной сетке. Плюсы: всё проверяется тестом `DungeonTest` без игры, «ближайший данж» для Осколка считается формулой, размер не ограничен 128 блоками от центра.

## Как данж попадает в мир
1. Мир поделён на клетки `cell×cell` (Разлом: 768). Для каждого типа в каждой клетке есть точка по сиду мира: `Dungeons.site(seed, def, cx, cz, attempt)`. Запасные точки (attempt 1..7, в пределах ±48) нужны, если центр в воде.
2. Игрок ближе `PREPARE_RANGE` (80) к точке — данж регистрируется в `DungeonData` (SavedData обычного мира): запоминается высота земли `y`, части, залы, возрождения.
3. Игрок ближе `PART_RANGE` (96) к части — её блоки ставятся порциями по `BUDGET` (1500) за тик. Когда часть дописана, в реестре ставится бит `partsDone`.
4. Данж «готов», когда построены все части; только тогда работают залы и мобы.

## Части (`.nbt`)
- Файлы `resources/data/explosionwand/structures/<имя>.nbt`, их делает `python tools/gen_dungeons.py` (стандартный формат структур Minecraft + теги `ew_origin`, `ew_marks`; в игре открываются `/place template explosionwand:<имя>`).
- Данж строится в «координатах данжа»: (0,0,0) — центр входа, y=0 — первый воздух над землёй. Генератор режет общую сетку на части; у каждой части в `ew_origin` её смещение, поэтому `Def` знает только имена частей.
- Части не должны пересекаться (проверяет тест). Размер части не ограничен; данж до ~250 блоков — несколько частей (тест `DungeonTest` собирает 4 части на 250 блоков).
- В клетках, которых нет в шаблоне, мир не меняется. Воздух внутри комнат нужно писать явно (`air`), иначе останется порода.
- `python tools/gen_dungeons.py --check` (запускается из `build.py`) сверяет файлы с генератором и проверяет, что блоки и мобы есть в реестре 1.20.1.

## Метки (`ew_marks`)
| Тип | Поля | Что значит |
|---|---|---|
| `start` | p | где стоит игрок у входа (для теста прохождения) |
| `door` | p, s, a | блоки двери (угол + размер); `a` — тип осколка, который отпирает (`rift`) |
| `brazier` | p, a | жаровня (`soul_campfire[lit=false]`); `a="dx,dy,dz"` — смещение до точки возрождения |
| `hall` | p, s, a | зал: угол, размер, номер (1..30); вход игрока будит зал |
| `spawn` | p, a | точка моба (`a` — id сущности), относится к залу, в который попадает |
| `chest` | p, a | сундук награды в зале; появляется, когда зал зачищен; `a` — название сундука |

## Правила внутри
- `DungeonGuard`: блоки не ломаются и не ставятся (не творческий режим), взрывы не рушат блоки, `EntityTeleportEvent` (жемчуг, хорус) отменяется, список палочек `DungeonGuard.forbidden` не срабатывает, элитры гасит `Dungeons.tick`.
- Мобы появляются при входе в зал (`PersistenceRequired`, теги `ewd`, `ewd<хеш>h<номер>`); пока ни один игрок не в данже 30 секунд — недобитые убираются и зал разбудится заново; зачищенный зал (`hallsCleared`) не оживает.
- Эффекты палочек, ставящие блоки напрямую (Разлом-каньон, Чёрная дыра, Ледяная буря, Хронос, Мимик, Посох Затмения), пропускают блоки данжа через `Dungeons.shield(level).at(pos)` / `Dungeons.protectedAt(level, pos)` — даже если колдуют снаружи. Новая палочка с прямой правкой блоков обязана делать то же.
- Зал не будится и не засчитывается зачищенным, пока сущности его чанков не загружены (`ServerLevel.m_143319_`, areEntitiesLoaded); после перезапуска отсрочка зачистки 30 тиков отсчитывается заново. В мирном режиме данж спит (мобы не появляются, зал не засчитывается). Мобы с тегом `ewd`, ушедшие дальше 24 блоков от границ данжа, убираются раз в 10 секунд.
- Если все 8 точек клетки в воде, данж в ней не ставится (`DungeonData.dead`), Осколок ведёт к другой клетке.
- Жаровня: ПКМ — состояние `lit=true`, точка возрождения хранится в `DungeonData.respawn` по ключу `uuid|ключДанжа`. Смерть внутри данжа + запись → возрождение там (`LivingDeathEvent` + `PlayerRespawnEvent`).
- Дверь: ПКМ по блокам двери с Осколком в любой руке открывает (блоки → воздух).

## Как добавить данж
1. В `tools/gen_dungeons.py` описать данж (функция вроде `build_rift_test`), метки, разрезание на части, имена файлов; `python tools/gen_dungeons.py`.
2. В `Dungeons`: `static final Def X = new Def("id", cell, margin, "part1", "part2", ...)`, добавить в `DEFS`.
3. Осколок: зарегистрировать `SealShardItem(props, "id")` в `ExplosionWandMod`, модель/текстура/рецепт/lang, ключи `explosionwand.dungeon.<id>`, `explosionwand.dungeon.locked.<id>`.
4. Тест: расширить `DungeonTest` (достижимость логова, ловушки).

## Ограничения 4.1
- Часть данжа ставится по `BlockPos` с флагом 18 (без обновлений соседей): ступени остаются «прямыми», жидкости не текут.
- Естественный спавн враждебных мобов внутри не отключён; свет стоит в каждой комнате (кристальный обсидиан, грибосвет, фонари).
- Ведро воды/лавы внутри блокируется только если Forge шлёт `EntityPlaceEvent` для ведра (проверить в игре).
- Огонь от взрыва «Орбитального удара» может ставить огонь в данже (блоки не ломаются).
